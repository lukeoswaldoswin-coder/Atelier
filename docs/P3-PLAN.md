# P3 实施计划：日历与手动排程

> 状态：**已实施并验收中（2026-11-14）**；实现与验证结果见 README「已执行的验证」。
> 基线：`p2-baseline`（`3b5b0a4`）。
> 依据：产品范围调整（轻量个人画师委托管理工具，简单辅助排期），P3 不引入 FullCalendar，使用自绘月/周视图。

## 1. 目标

1. 任务可以设置「计划日期」，与委托截止日期**完全独立**。
2. 月视图 / 周视图查看任务计划与委托截止。
3. 手动安排、修改、清除任务的计划日期。
4. 展示「未安排任务」列表。
5. 为 P5 的简单辅助排期提供可靠数据（P3 不做推荐算法）。

## 2. 非目标（P3 明确不做）

- 拖拽排期、小时粒度视图；
- 每日绘画容量、可绘画时间窗口；
- 自动排班、依赖关系、自动拆分；
- 修改委托截止日期；
- 独立任务总览页（任务仍在委托详情与日历中管理）。

## 3. 关键决策

| 决策 | 说明 |
| --- | --- |
| 不引入 FullCalendar | 只有日期粒度、无小时视图与拖拽；自绘月/周网格更轻、可测试性更好，不新增依赖 |
| 日期只存 `YYYY-MM-DD` | 计划日期是纯日历概念，不做时区换算 |
| 单任务单计划日期 | 一个任务一个 `planned_date`；多日任务在后续阶段再评估 |
| 已完成任务保留计划日期 | 完成操作不清除 `planned_date`，日历中与未完成任务视觉区分 |
| 计划日期可清空 | 传 `null` 清除，任务回到「未安排」（若它未完成） |

## 4. 数据模型（迁移 004，仅追加列）

```sql
ALTER TABLE tasks ADD COLUMN planned_date TEXT
  CHECK (
    planned_date IS NULL
    OR (
      planned_date GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'
      AND date(planned_date) IS NOT NULL
      AND date(planned_date) = planned_date
    )
  );

CREATE INDEX idx_tasks_planned_date ON tasks (planned_date);
CREATE INDEX idx_tasks_unscheduled ON tasks (commission_id)
  WHERE planned_date IS NULL AND archived_at IS NULL AND status <> 'done';
```

- 不重建 `tasks` 表、不改编排、不删除行；既有任务升级后 `planned_date` 为 NULL。
- 迁移前自动 `VACUUM INTO` 备份（沿用现有机制）。
- 领域模型 `Task` 增加 `plannedDate: string | null`；创建/更新输入增加 `plannedDate`（`nullish`）。

## 5. `tasks:update` 的部分更新语义（硬约束）

| 传入 | 结果 |
| --- | --- |
| 不传 `plannedDate` | 保持原值不变 |
| `plannedDate: null` | 清除计划日期 |
| `plannedDate: 'YYYY-MM-DD'`（合法、真实存在） | 更新为该日期 |
| 非法格式 / 不存在的日期 | Zod 或 DB CHECK 拒绝，整条更新回滚 |

- 仓储层必须用 `!== undefined` 判断，不能用真值判断（`null` 是有效值）。
- 该语义同样适用于 `estimatedMinutes`、`description` 等现有可空字段，测试要覆盖。

## 6. 查询与过滤规则（硬约束）

1. **已取消、已归档的委托**不参与正常日历，也不进入未安排任务列表。
2. **已完成委托**保留历史计划日期并继续在日历展示，但**不进入未安排任务列表**。
3. **已完成任务**保留原计划日期，不因完成操作被清除；日历中与未完成任务视觉区分（例如弱化 + 勾选标记）。
4. **未安排任务**只包含：任务未完成、任务未归档、`planned_date IS NULL`，且所属委托为 `draft` 或 `active`。
5. `plannedDate` 与委托 `deadline` **完全独立**：修改任意一个都不影响另一个；不做级联、不做自动同步。
6. 日历范围查询：`from` / `to` 均为 `YYYY-MM-DD`，闭区间；`from > to` 拒绝。

## 7. IPC 契约

| 通道 | 输入 | 输出 |
| --- | --- | --- |
| `calendar:tasks` | `{ from: date, to: date }`（strictObject） | `{ scheduled: CalendarTask[], unscheduled: CalendarTask[] }` |

```ts
interface CalendarTask {
  task: Task
  commission: {
    id: string
    title: string
    status: CommissionStatus
    priority: number
    deadline: Deadline
  }
  clientName: string
}
```

- `scheduled`：计划日期在 `[from, to]` 内、任务未归档、所属委托未归档且未取消（含已完成委托与其已完成任务）。
- `unscheduled`：按第 6 节规则 4 过滤；排序：委托截止紧急度 → 任务阶段 → `sort_order`。
- 计划日期写入复用 `tasks:update { id, plannedDate }`，不新增写通道。
- 输出经过 Zod 校验，不接受前端构造的视图模型。

## 8. 界面

### 8.1 日历页（替换 P3 占位页）

- 月视图：周一为起始，6×7 网格；今天高亮；上一月 / 下一月 / 回到今天。
- 周视图：7 列日期列表（日期粒度，不做小时网格）。
- 日期格内容：
  - 任务条目：阶段色点 + 标题；已完成任务弱化并带勾选；每格最多 3 条，其余显示「+N」。
  - 委托截止：独立标记（琥珀色），不与任务混排；日期型原样显示，时刻型按创建时区显示时间。
- 点击任务：小面板显示委托 / 客户 / 阶段 / 预计工时，操作：修改日期、清除计划、查看委托（跳转委托详情）。
- 空状态：当天无安排时显示轻量提示。

### 8.2 未安排任务面板

- 列表字段：任务标题、阶段、预计工时、委托标题、客户名、委托截止。
- 每条提供日期输入 + 「安排」；保存后立即从面板移除并出现在日历。
- 排序：逾期委托优先 → 截止更近优先 → 预计工时。
- 空状态：没有未安排任务。

### 8.3 日期交互

- 允许安排到过去日期（补录场景），但显示「过去日期」提示，不阻断。
- 清除计划日期后：任务从日历移除；若未完成且委托为草稿/进行中，回到未安排列表。

## 10. 测试计划（对应硬约束）

1. **迁移 004**：新库列/索引正确；从 003 升级保留既有客户、委托、任务行；SQL CHECK 拒绝非法日期。
2. **部分更新语义（规则 6）**：不传保持、`null` 清除、合法日期更新、非法日期拒绝；其它可空字段同样覆盖。
3. **规则 1**：已取消、已归档委托的任务不出现在 `scheduled` 与 `unscheduled`。
4. **规则 2**：已完成委托与其历史任务仍出现在 `scheduled`，但不出现在 `unscheduled`。
5. **规则 3**：任务完成不清除 `planned_date`；日历中已完成任务带独立样式。
6. **规则 4**：未安排列表只含未完成、未归档、委托草稿/进行中的任务。
7. **规则 5**：修改 `plannedDate` 不影响 `deadline`，修改 `deadline` 不影响 `plannedDate`（双向测试）。
8. **规则 7**：月视图（月份边界、闰年、周一起始）、周视图、任务日期、截止日期各自独立测试。
9. 日历范围闭区间、`from > to` 拒绝；日期字符串无时区漂移。
10. UI：安排后从面板消失并出现在对应日期；改期日、清除日期；跨月导航；「+N」溢出。
11. 回归：任务 CRUD、状态联动、委托列表/详情/筛选不受影响。
12. 真实数据保护：迁移在真实库副本上验证（当前 1 客户 / 1 委托 / 0 任务），升级后行数不变。

## 11. 验收标准

1. 任务计划日期与委托截止日期在数据与界面完全分开。
2. 第 5 节四种部分更新语义全部正确。
3. 第 6 节四条过滤规则全部正确。
4. 月/周视图、任务日期、截止日期均有独立测试且通过。
5. 已完成任务保留计划日期并在日历中可区分。
6. 迁移 004 仅追加列，已有数据零丢失。
7. `typecheck / test / build / smoke` 全绿，视觉验证通过。

## 12. 风险与边界

| 风险 | 缓解 |
| --- | --- |
| 日期计算时区漂移 | 纯 `YYYY-MM-DD` + UTC 运算，独立单元测试覆盖月末/闰年 |
| 大量任务导致单元格拥挤 | 每格最多 3 条 + 「+N」，点击日期查看全部 |
| 已完成任务长期堆积 | P3 接受；后续可加「隐藏已完成」开关（不在 P3 范围） |
| 真实库迁移 | 仅追加列 + 迁移前自动备份 + 行数校验 |
| 计划日期被误改 | 修改需显式操作；P5 推荐必须用户确认，不覆盖已有日期 |
