### 3.2 如何避免重复记账（本阶段最关键的架构点）

任务计时会话**本身就是一条 `time_entries` 记录**，只是满足：

```
source = 'auto'  AND  task_id IS NOT NULL  AND  status = 'running'
```

而普通自动片段满足 `source = 'auto' AND task_id IS NULL`。两者共用同一张表，
因此天然受迁移 005 已有的唯一索引约束：

```sql
CREATE UNIQUE INDEX ux_time_entries_auto_active ON time_entries (source)
  WHERE source = 'auto' AND status = 'running' AND deleted_at IS NULL;
```

**这意味着：同一时刻数据库只允许存在一条 `running` 的 auto 记录。**
任务会话与普通自动片段在数据库层面互斥，重复累计不是靠应用层自觉，
而是被约束拒绝。已用真实文件数据库实测验证（见五.2）。

配套的应用层改动：

1. `findActiveAuto()` 改为只取 `task_id IS NULL` 的行，新增 `findActiveTaskSession()`
   只取 `task_id IS NOT NULL` 的行——避免把任务会话误当普通自动片段结算。
2. 监测的 `evaluate()` 中任务会话**优先**：有会话时只调用
   `applyTaskActivity(active, appKey)`，并 `closeAuto()`，绝不创建独立自动记录。
3. 开始任务会话时先 `closeActiveAuto()`，保证不会撞唯一索引。

### 3.3 自动监测关闭时为何仍能累计

原实现的 `tick()` 与 `restartTimer()` 都被 `config.enabled` 卡死。改为：

- 采样条件：`config.enabled || timeService.hasTaskSession()`
- 会话活跃判定**不看** `config.enabled`（会话由用户主动开启，属于用户明确意图）
- 会话开始/结束时通过 `onTaskSessionChanged` → `monitor.refreshTimer()` 按需启停定时器

没有任务会话且监测关闭时，仍然完全不采样、不加载原生探测（保持 P4 行为）。

### 3.4 两个时间如何区分

| 指标 | 含义 | 计算方式 |
|---|---|---|
| 实际累计工时 | 只有绘画软件活跃的时间 | 活跃片段单调时钟累加 |
| 会话持续时间 | 点击开始到现在的墙钟时间 | `wallMs() - startedAtWall` |

实机验证示例（`report.json`）：`{"accumulated":3,"session":3}` 以及
`{"accumulated":3300,"session":5400}`（55 分钟 / 90 分钟）——两者确实独立。

## 六、尚存限制

1. **框选/列表细节**：本阶段未实现任务列表的拖拽排序，任务顺序沿用既有
   `stage + sort_order`，排序仍需在委托详情里操作（不改变既有管理方式）。
2. **「跳转到所属委托详情」**：目前点击「查看委托」切到委托管理页，
   但不自动定位到具体委托（委托页没有接收外部选中项的入口，新增会牵动 P1.2 的
   store 契约）。属于最小改动取舍，未擅自扩展。
3. **「更多操作」**：任务行只提供开始计时 / 标记完成 / 查看委托三项，
   编辑、归档、改阶段仍在委托详情里完成，避免出现第二套编辑入口。
4. **会话不自动结束**：按需求设计，会话只在用户手动结束时结束；
   极端情况下用户忘记结束，会一直保持 running（重启后恢复为进行中）。
   未加自动超时结束，因为需求明确「软件不活跃不代表会话结束」。
5. **24 小时上限**：手动计时有 24 小时自动暂停，任务会话**未加**该限制。
   原因是任务会话累计的是活跃时间而非墙钟时间，正常不会触及；
   如需一致行为可在后续补充。
6. **未升版本号**：仍为 0.1.1，未重新打包安装包，未创建 `p6.6-baseline`，
   等待验收后再决定。

## 八、环境说明（新增 1 条）

**项目目录内的 Electron 二进制无法启动**：直接运行 `node_modules/electron/dist/electron.exe`
会立刻崩溃。仓库自带的 `scripts/electron-runtime.mjs` 已有自检，
会自动使用工作区外的副本 `D:\Atelier\atelier-electron-runtime`。
本阶段实机验证脚本已改为复用它（`ensureElectronRuntime()`），
不再依赖手工指定 `ATELIER_ELECTRON_BIN`。

另：沙箱内 `spawn` 用管道捕获子进程输出会 `EPERM`，实机脚本改为把
Electron 输出重定向到临时日志文件。
